# Harness 数据可视化规格

本文规定[分支 Agent 开发文档](../分支Agent开发文档.md)中同页“运行与数据”区域的展示、导航和验收要求。数据字段、类型与关联以 Harness 数据契约为准；本页不另建业务数据副本，不把浏览器状态作为执行事实来源。

## 1. 同页入口与展示原则

对话页面包含三个可同时保留状态的区域：主对话区、配置区、运行与数据区。后两者默认收起，用户只通过对话即可完成改编，无须选择内部 Agent、Session 或数据库记录。

- 点击阶段产物、任务进度、历史消息的“查看数据”，直接在运行与数据区打开对应记录；打开、筛选、比较和复制均不改变运行状态或确认状态。
- 切换数据页签不清空对话输入草稿、不切换项目、不重启任务。关闭数据区后保留本次查看位置。
- 默认显示中文字段名、状态和简短说明，同时提供技术字段名。ID 可复制，关联对象可点击跳转。
- 所有记录提供结构化详情；可公开的持久字段同时提供只读 JSON 详情。大型正文或外置内容通过固定版本引用按需展开，不在每个列表中重复加载。
- 记录正文、原作和模型输出一律作为数据渲染；JSON 和代码按文本显示，不执行其中的 HTML、脚本或指令。
- 展示事实来自服务端。无记录、未执行、尚未统计、读取失败分别显示；未知费用、token 数和耗时不能显示为 `0`。
- 主对话区提供服务端生成的待处理卡片：确认／修改按钮、建议选项、自定义回答、预算与故障恢复表单。数据检查器仍用于查看证据，不承担唯一操作入口。表单绑定固定对象及状态版本，刷新保留草稿，陈旧表单拒绝执行；具体接口见 [结构化待处理卡片](storage-and-api.md#55-结构化待处理卡片)。

## 2. 记录导航与视图

顶部固定显示当前项目、用户可见会话，以及可选的阶段、章节、任务筛选。下表各类记录都必须有可发现的入口；不要求为每种表单独建立一个页签。

| 入口 | 列表或概览 | 详情与关联 |
| --- | --- | --- |
| 项目与会话 | 项目名称、会话标题、最近活动、实际任务状态 | 账号归属、创建／更新时间、会话列表、相关任务、产物与内部工作 Session；平台登录凭证不进入此视图 |
| 原作与附件 | 名称、格式、版本、解析状态、内容大小 | 固定版本原文、解析结果、内容引用、来源索引和片段定位；附件读取受项目权限控制 |
| 原始记录 | 用户／Agent 消息、内部阶段和子任务消息、工具事件的时间线 | 原始内容、发言方、阶段／章节、所属任务／运行／Session、关联产物、回复或来源记录；用户可见对话与内部记录明确标记 |
| 工具执行 | 工具名、开始时间、结果状态、耗时 | 调用参数、可读取结果或错误、发起模型调用、实际执行 Run、对应工具结果记录；跨 Run 恢复显示两者及恢复依据，重试的多次尝试分别可查 |
| 工作 Session 与摘要 | 协调、阶段、章节、审核等工作范围，当前状态与最近活动 | 关联运行、当前工作内容、摘要版本、原始归档引用、压缩／裁剪／重建记录；摘要显示覆盖范围、引用版本、校验和有效性 |
| 任务、运行与队列 | 任务目标、Agent、阶段、状态、等待／暂停原因、队列顺序 | Task 与各次 Run 的关系、父子任务、执行范围、Steer／Queue 来源消息、已消费与待处理请求、重试／修复计数和恢复记录 |
| 检查点 | 所属任务／运行、保存时间、原因、有效性 | 已完成与待完成范围、固定依赖、配置快照、累计用量、可恢复位置及失效原因；通过引用查看相关记录 |
| 产物与版本 | 产物类型、阶段／章节、草稿与当前有效版本、依赖状态 | 完整正文或 Graph JSON、Schema 版本、来源、依赖、生成运行、配置快照、版本比较、确认和替代记录 |
| 决策与确认 | 事项、选定／否定结果、适用范围、实际状态 | 原始用户消息、明确记录的理由、固定产物版本、字段或条目范围、替代／撤回关系；缺少理由显示“未记录” |
| 依赖与检查 | 当前产物的直接上游／下游、依赖有效性；已有程序检查和审核报告 | 版本化依赖、影响范围、需复核原因、检查对象与结果、审核问题的定位和修复记录 |
| 模型调用与上下文 | Agent、模型、阶段、调用状态、轮次、耗时与用量 | 当次实际参数、instructions、工具定义、输出类型、输入清单、材料加载／省略原因、实际发送的可展示输入和返回输出 |
| 配置与运行快照 | 已发布配置版本、运行绑定快照、作用范围 | 继承结果、提示词／Schema／映射／校验器版本和哈希、实际模型参数、与当前发布配置的差异；进入同页配置区新建编辑草稿 |
| 其他内部记录 | 按数据契约中的记录类型查询 | 统一结构化详情、JSON、关联引用；新增内部记录类型不能因尚无专用视图而完全不可查看 |

同一记录可从多个入口访问，必须指向相同服务端记录，不复制为相互独立的“展示记录”。工具输出和模型输入中引用的外置正文可在侧栏打开并返回原调用。

## 3. 通用详情、筛选与分页

### 3.1 固定对象与跳转

详情标题始终显示记录类型、稳定 ID、内容版本（适用时）、创建时间和当前业务状态。记录 ID、内容版本与状态更新时间分别展示，避免把状态更新误认为正文改版。

- 从历史调用、确认、摘要或依赖点击的链接必须打开其引用的固定版本，不能自动跳到最新版本。
- 版本化对象提供“当前有效版本”和“最新草稿”入口；无有效版本时明确显示，不以草稿替代。
- 内部关联携带完整项目上下文。被删除、缺失、无权访问或内容暂时不可读时显示具体类别，不编造内容；无权访问时不泄露其他项目元数据。
- 刷新或重新登录后，服务端鉴权通过的页面定位仍可打开；页面地址和前端状态不承载 API 密钥、正文或恢复凭证。

### 3.2 列表规则

列表至少支持记录类型、时间范围、阶段、章节、任务／运行、Agent 和状态筛选，并支持按精确记录 ID 定位。只有适用于该记录类型的筛选项才启用；筛选改变时重置分页。

- 原始消息默认按时间顺序展示；任务、调用、产物等列表默认最近更新在前。相同时间用服务端稳定顺序继续排序。
- 初始每页 50 条，单页最多 100 条，采用服务端游标分页；大文本、工具结果和上下文内容独立分页／展开，不一次加载整个项目。
- 分页固定查询边界或快照，防止后台新增记录造成跳行和重复；新记录以“有新记录”提示或独立增量插入，不打断当前历史阅读。
- 筛选只改变展示，不删除历史，不改变 Session 的上下文取用规则，也不触发模型检索调用。
- 读取失败提供重试；空结果显示筛选条件和“无匹配记录”。不得把读取失败显示为无记录。

### 3.3 JSON 详情

JSON 详情显示服务端返回的记录内容与契约版本，支持折叠、字段搜索和复制。外置内容明确显示为内容引用，点击后读取；不要把未加载内容伪装为 `null` 或空字符串。

如果字段被安全规则遮蔽，使用明确的遮蔽标记和原因，并说明这是展示副本。记录 JSON 复制与最终 Nexo Graph 下载是两个独立操作；前者不能替代最终产物导出。

## 4. 版本、确认与依赖

### 4.1 版本比较

用户可以选择同一产物的任意两个有权读取的版本进行比较；默认比较当前有效版本与最新草稿。比较明确标出版本、Schema、产生时间和生成来源。

- 正文使用逐行文本差异；结构化产物使用字段路径和增删改列表。
- 对具有稳定条目 ID 的数组按 ID 对齐；无稳定 ID 时按原顺序比较并标明此方式，不能凭标题或相似文本自动认定为同一条目。
- Schema 版本不同时显示差异及兼容性说明；无法作字段级对比时仍提供两侧 JSON，不在查看时迁移或覆盖旧版本。
- 只展示实际确认范围。部分确认、待确认、已被替代和依赖失效分别标记，不用一个“已确认”标签掩盖范围差别。

### 4.2 确认与决策来源

确认详情展示“用户消息 → 固定产物版本 → 确认范围”；决策详情展示用户提出、Agent 建议、用户确认等来源区别，以及有明确记录的选定／否定理由。点击来源可查看原始消息及相邻上下文。

依赖失效不删除历史确认。界面同时展示“曾确认的范围”与“目前是否可继续使用”，并提供产生变化的上游版本和处理记录。

### 4.3 关系图

首版使用以当前选中记录为中心的简要关系图和同内容关系表，显示直接上游与下游。节点标识记录类型、名称、版本和状态，连线标识来源、依赖、确认、生成或替代关系。

默认仅展开一层，最多展示 50 个节点；更多关系通过筛选、分页或选中节点后继续展开。图不绘制整个项目的所有记录，也不承担 Nexo 剧情树编辑功能。关系表必须提供等价导航，避免关系密集时无法操作。

## 5. 运行、上下文与用量

### 5.1 执行时间线

任务详情按实际事件展示接收请求、开始 Run、模型调用、工具执行、保存产物、等待输入、暂停、恢复和完成等事件。每个事件关联来源记录及服务端时间。

- 单独展示用户选择的 Steer 或 Queue、收到时间、实际应用／开始处理时间以及处理状态；收到不等于已生效。
- 当前调用仍在执行时显示真实状态；用户请求停止后，应区分“停止请求已提交”和“已停止”。
- 恢复须显示使用的检查点、依赖检查结果、续用配置快照和新的运行记录；查看检查点不自动恢复。
- Task 与 Run 分别显示状态：Run 成功、Task 等待确认时，页面不能显示整个任务完成。Run 的 runner／recovery 类型分别标为“Agent 执行”／“程序恢复”；后者没有模型调用，不能补造模型输入或轮次。
- 队列显示 hold 原因、阻塞任务和依据；“继续任务”与“继续队列”分别调用对应命令，后者不会恢复被停止的任务。解析中、依赖阻塞、已派发与业务完成分别展示。
- 恢复详情显示自动恢复累计次数、上限、下一次尝试时间，以及原轮次额度、已用和余额。服务重启后的新 Run 不显示成重新获得完整额度。
- 失败尝试、超限暂停和旧依赖上的迟到结果继续保留。不能因之后成功而隐藏此前的错误或费用。
- 页面仅提供主文档已规定的停止、继续和明确追加额度等控制，复用相同服务端命令；不新增任意修改状态、跳过确认或从历史检查点强制覆盖现状的入口。

### 5.2 上下文查看

每次模型调用展示固定的输入构成：instructions、当前请求、近期历史、工作摘要、产物／原作片段、工具定义、运行中工具结果，以及它们的来源和版本。

材料清单至少可区分已加载、按需未加载、因去重省略、因预算裁剪或转为分批处理；后两种状态不适用于 Step1 的完整原文。Step1 展示全文固定版本与实际加载范围，缺少任何正文时不能显示全文已加载。记录存在于归档不代表已进入本次模型上下文。点击每项可查看当次内容或固定引用，而不是当前最新版。

同时展示输入预算、估算 token、服务端返回的实际用量（可获得时）和发生的压缩／分批记录。估算与实际值分别标识；摘要展示覆盖范围、遗漏或待处理事项和有效性，不宣称摘要可还原全部原始交互。

### 5.3 用量展示

首版使用调用列表与汇总数字，按任务、运行、Agent、阶段汇总；无需独立分析仪表盘。

- 展示模型调用次数、输入／输出 token、缓存或推理 token（提供时）、已计费金额与币种、任务活动耗时、限额及剩余额度。
- 调用耗时、任务活动耗时、排队时间和等待用户时间分别命名；不把全程墙钟时间当作活动预算消耗。
- 重试、修复、摘要和子任务的实际调用计入关联任务；汇总以调用唯一标识去重，父子层级不能重复相加。
- 模型没有提供某项用量，或尚无适用价格配置时，显示“未提供／未计算”；估算费用须有估算标记及计价版本，不展示成已结算金额。
- 额度追加单独显示记录和生效时间。历史累计用量保留，恢复后不显示为归零。

### 5.4 材料覆盖与版本影响

按[上下文执行方案](../context/上下文执行方案.md)展示阶段材料清单。Step1 展示原作固定版本、全文 token 数、其他必要输入、原文上限、阶段总输入上限、输出上限／预留、安全余量、有效输入预算 `B` 及准入结果；同时显示所选模型的上下文窗口和输出能力。超限显示实际限制和处理方式，不显示批次或批次覆盖进度。模型调用详情标明全文是否完整加载；生成、修正及重试均可检查。

其他适用阶段展示 batch_manifest 固定计划及逐批执行事件。列表显示主要范围、邻接范围、已处理／待处理单元、结果引用、跨批未解决事项和恢复复用依据；点击正文范围跳到对应 source_text 固定版本。邻接读取、摘要覆盖和正文任务完成分别展示，不能混为全量完成。

按[版本与确认映射](../context/版本与确认映射.md)展示新旧条目身份、字段变化、依赖影响、程序核验／Agent 分析依据、保留的确认范围和仍需用户决定的范围。配置中的字段映射预览与正式已提交映射分开；浏览、比较和预览不生成确认。

同页配置区提供阶段材料字段选择、自动／按需加载及优先级。Step1 完整原文为固定必需材料，`context.step1_source.mode=full_text` 与 `overflow_behavior=reject` 只读；阶段配置中可调整 `context.step1_source.max_source_tokens`、`context.input_token_cap`、`model.max_output_tokens`、`context.safety_margin_tokens`，默认依次为 200000、256000、32000、2000 tokens。其他阶段默认输入 32000、输出 8000、安全余量 2000；默认模型 `gpt-5.6-sol`、推理强度 `medium`。每个可调项显示继承后的实际值、来源与版本；所选模型的窗口和最大输出能力单独显示。

页面实时预览 `B = min(解析后的阶段 context.input_token_cap, 模型上下文窗口 − model.max_output_tokens − context.safety_margin_tokens)`，输出预留包含推理与可见输出。原文上限是项目准入限制，不是模型能力；原文通过后仍需以全文和其他实际输入检查 `B`。Step1 必需全文高于 75% 软阈值但在 `B` 内时保留，不能显示为必须压缩或触发循环压缩。超限可调整有效配置／受支持模型，或由用户明确提供新的完整较短作品版本，不提供自动截断、摘要替代或分批开关。

后续适用阶段另提供批次大小、自然边界、邻接和衔接预算。参数初值以 [defaults.json](../context/defaults.json) 为准；发布后按运行快照生效，不通过前端编辑直接改变正在执行的计划。

## 6. 只读边界与权限

所有数据读取、分页、关联跳转和内容下载由服务端校验平台账号及项目权限。客户端筛选与隐藏按钮不构成权限控制。不能通过手填 ID 访问其他账号或项目记录。

运行与数据区中的历史消息、工具记录、产物版本、确认、决策、调用输入、配置快照和检查点均不可原地编辑。用户要修改创作内容时回到对话提交要求，配置修改进入配置草稿；接受变更后按既有业务规则保存新版本、新事件或新的有效状态。列表展示的当前状态可以随着新业务事件更新，历史依据持续保留。

不得展示或复制 API 密钥、认证 token、Cookie、服务端连接凭据和其他运行秘密。模型内部隐藏思维链、不可读 reasoning 载荷、凭证或不透明恢复数据不作为可展开正文；可显示它们存在的安全元数据。提供商实际公开的简短摘要如有保存，应标为“公开摘要”，不得冒称完整内部思维过程。

对话／工具／上下文里含有的普通业务内容按项目权限可读；为遮蔽秘密而形成的显示副本须明确标记，不改写被引用的业务版本或制造不存在的历史。页面不提供删除审计依据、篡改数据库字段、强制通过检查或清空预算的控制。

## 7. 可验证验收

以下场景使用保存好的示例记录或一次真实运行验证页面行为，不要求建立 Harness 自动评测系统。

| 场景 | 验收结果 |
| --- | --- |
| 用户仅在主对话操作 | 无需展开内部数据区即可提交原作、修改、确认并下载最终 JSON |
