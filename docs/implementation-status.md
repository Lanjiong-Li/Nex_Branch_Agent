# 本地版交付与验证状态

更新：2026-09-21。代码位于本项目 `branch_agent/`；启动与操作见 [README](../README.md)。本页记录当前可运行实现，主开发文档保留完整设计要求。

## 可运行的交付

- FastAPI 同源对话页面、本地持久账号、项目与多会话、TXT／Markdown／DOCX 原作导入。页面提供 Steer／Queue、停止、继续和耗时追加入口。测试版已关闭费用门禁及费用追加／确认／补录入口，保留费用统计。
- 真实 OpenAI Agents SDK 适配，1 个协调 Agent、6 类专业 Agent，Step1–11 和逐章循环。所有模型使用 Responses API，默认 `gpt-5.6-sol`／`medium`，可选择已注册的 Mini／Nano 模型。
- 15 种严格输出 Schema，7 类 Agent 的 instructions、阶段／辅助任务配置、模型及上下文预算编辑；草稿发布后生成不可变运行快照。辅助摘要和批次子任务沿用父任务冻结的配置。
- PostgreSQL 中的 22 类记录、不可变历史／产物版本、CAS、项目隔离、原始归档、固定引用、任务队列、租约与恢复检查点。模型调用记录真实输入、输出、用量和耗时；费用按当前运行固定价格表估算。
- Step1 每次读取全部原文，默认原文 200000、输入 256000、输出 32000 tokens。覆盖锚点支持可信 UTF-16 起止位置，避免为记录覆盖范围重复输出整本原作。
- 按阶段选择材料，必需字段完整保留，可选自动材料按优先级裁减；会话压缩生成有归档来源的结构化摘要，保存旧历史和摘要版本。摘要输入不展开供应商推理项中的不透明密文，只保留固定归档引用及实际返回的元数据和摘要；原始归档、SDK 恢复数据与供应商响应保持完整。只自动载入当前 Session 的最新摘要；已在工作历史中的同版本摘要不重复拼接，其他 Session 的摘要按需检索。当前材料已经固定新版时，自动追溯得到的同一产物旧版只保留原证据引用，不重新展开为当前阶段的必需正文；显式历史读取仍返回原固定版本。只读工具支持跨 Session 检索及固定版本分页读取。
- 明确用户消息、所展示版本和范围共同决定确认；历史摘要或模型文字不能直接成为确认。修改上游后使相关下游失效，要求复核。
- 批次缺少必要信息时，把原问题展示在同一对话中；答复记录到具体待办，继续原批次的 Session、配置和覆盖账本。已完成批次不重跑，已保存的模型结果优先经正常门禁复核。
- 章节 Graph 按固定基线合并，保护已有身份、类型和布局，显式记录删除。程序执行 Schema 与不可达节点检查；可选校验 Agent 默认关闭，instructions 非空时只读取最终 Graph。通过后交付同一 Project JSON，页面可查看、复制、下载。
- Step10 模型仅使用本章已确认设计、对应原文及 instructions，按 `chapter_graph` output_type 生成；Graph 基线和写入上下文只由 Harness 在程序内使用。Step11 不读取其他阶段材料或会话历史。
- 同页配置区与数据检查器：Schema 字段树／JSON、22 类记录、真实上下文、来源跳转、依赖关系、版本差异、调用耗时及用量。
- 模型终态在 SDK 校验前归档。输出截断、内容策略、明确失败、拒答及常见 HTTP 错误分别显示受控原因；真正无终态的传输异常仍保留 unknown。已知失败响应缺少用量时保留费用未知；测试版不因此阻断，也不视为零费用。页面可从父任务跳到当前阻断子任务及其具体运行，见[错误分类与展示修复](error-reporting-fix.md)。
- 主对话区提供“待你处理”卡片：固定版本确认／修改、逐题选项和自定义回答、原配置续跑、新配置重跑／从 Step1 重建及逐条队列恢复／取消。操作直接进入服务端校验，不经过协调模型猜测按钮含义；待办、依赖或配置变化后拒绝旧卡片，刷新保留输入草稿。协调 Agent 的澄清和章节规划修改也进入此流程。详情见[结构化操作交付记录](structured-actions.md)。

## 已验证与尚待验证

自动测试使用真实本地 PostgreSQL 的隔离 schema。SDK 集成测试使用实际 `Agent`／`Runner` 和明确的模拟 HTTP 供应商；工作流测试使用明确的测试模型，覆盖两章 Step1–11、确认、审核与同版本交付。这些测试不代表真实模型创作验收。

自动回归：`.venv/bin/python -m pytest -q` **289 项通过**（仅一条第三方弃用警告）；前端工具测试 **27 项通过**。新增覆盖两项脚本校验、无入边节点、恒假条件路径、未知 DSL 的保守处理、校验 Agent 默认关闭、非空 instructions 启用、仅传最终 Graph，以及脚本失败原因进入对话。输出 Schema 离线合同校验通过。正式本地启动脚本已验证，健康检查返回 200，后台调度器开启。

真实短篇《一盏灯》已完成 Step1–11 及其模拟用户确认。Step10 从余额不足的原暂停任务恢复，正式审核指出两个条件节点缺少默认阻断分支；章节写作 Agent 生成返修版本并重新取得固定版本确认，随后 Step11 返回 `pass`、`findings=[]`。程序复核已保存结果后自动交付同一 Graph，无审核后的二次确认，也没有重发已成功的模型请求。当前无运行中、排队、等待或暂停任务；早前失败子任务和旧歧义请求保留为历史记录。

最终 [Nexo Graph](../artifacts/live-smoke.nexo.json) 为固定产物 `5205d440-35dc-4fdc-b60b-e1ac1629d827` v11，1章、10节点、10边，保留原来的两个剧情结局。Schema 与章内端点检查通过；原9个节点所有字段均未改变，仅新增两个默认出口及一个无出边的阻断节点。源码解析器核对两条赋值和两条条件有效；这是静态核对，不代替播放器执行验收。

Chrome 已通过真实页面打开最终交付并下载 JSON，11139字节，SHA-256 为 `379c2389ad60f9a5e5fd23149efe4a2415405afb422691f75652b1454be88399`，与固定版本的 `content_sha256` 一致；解析内容也与程序导出相同。浏览器控制台错误、HTTP 错误和业务写入尝试均为0。失败调用记录可正常展开，HTTP200 记录自身的 `error` 字段不再误判为接口失败，非2xx错误仍正常报错。临时只读验收服务及临时凭据已清理，默认8767服务继续运行。详见[页面验收记录](implementation-ui-report.md)。

当前验收工程累计102次真实请求：100次成功，2次为先前余额不足的明确拒绝；用量／结果未知请求为0。工程归档估算费用18.8119380 USD；本次补款续跑新增22次请求、5.1240268 USD；加上先前两个排错尝试的全部联调费用为19.3704592 USD。验收过程中通过正式配置发布将该测试项目的协调 Agent、Step8–11 和辅助摘要的新任务输入上限提高到64000、历史目标提高到12000；旧任务冻结配置不变，不能将此结果宣称为全程使用默认32000输入预算。所有确认均为隔离测试中的模拟用户消息，不能代表真实人工审核。真实模型生成由 API／Engine 驱动，浏览器只读核验历史和下载。本次仅证明一个短篇样本，未验收长篇、平台账号、服务器部署或 Nexo 导入／发布／播放。测试项目保存在独立数据库 schema，与默认应用项目列表分开；固定引用及证据见[真实模型记录](live-model-smoke.md)。

服务端已修复终端遗留 key 覆盖问题：当前本地应用优先使用项目 `.env` 的 API key，无项目 key 时使用环境变量。不要将密钥写入浏览器配置或对话。

## 当前实现边界

| 项目 | 当前行为 |
| --- | --- |
| 长材料 | Step2–8 可按固定版本展开为实际批次子任务，并检查覆盖。所有批次结果汇总后仍超预算会暂停；尚无递归多级汇总。Step9／10 的完整正文和 Step11 的完整候选超过预算时暂停，需提高对应阶段配置，不能改用摘要冒充完整内容。 |
| 压缩时机 | 在进入新的 `Runner.run()` 前压缩历史；工具调用与结果必须成对闭合，用户请求可以仍待最终答复。若保留近期完整工具链会使摘要无法放入硬预算，可一并归档压缩，摘要保留未完成请求与已完成工具结论，原用户请求重新提供；实际新输入通过硬预算后才替换工作历史。一次 Runner 内超限仍保存进度并暂停，尚无运行中原地压缩适配。 |
| 依赖与确认继承 | 当前采用整产物的保守失效，程序仅更新方案的阶段引用目录时有专门例外。尚未实现可配置字段转换、语义保护范围和跨版本确认继承证明；相关非默认配置发布会被拒绝。保留的 `selected_with_guards` 配置值不表示该高级策略已经执行。 |
| Schema 修改 | 可以编辑兼容字段及模型生成的扩展字段；已有消费者依赖字段、程序生成字段和阶段语义绑定受保护。任意字段改名、输出根替换、消费／导出映射需要新增服务端适配，不能仅修改 Schema 后自动生效。 |
| 检查点 | 关键确认、阶段推进、待输入及恢复门禁保存检查点；检查点事件选择当前固定，改为未支持的事件在发布时拒绝。 |
| 模型与计量 | 只支持已注册能力的模型。请求前 token 数为本地估计，返回后保存实际用量；价格为版本化估算，已计入供应商返回的缓存读取／写入信息，未返回的用量保持未知。 |
| 账号与部署 | 本地测试账号可跨重启读取同一数据库历史；尚未连接正式工具平台账号。已提供 Dockerfile／Compose，但没有启动 Docker 环境验收，也未部署服务器。 |
| 结构化重开 | 尚未交付的项目支持从 Step1 重建；已有交付 Graph 时不自动删除旧章节，全剧重开按钮禁用并指向按阶段修订或新建项目。真正远端结果未知的调用须核实后才能重做，不能通过界面确认假定其失败。 |

Nexo 编辑器嵌入、自动写入／发布、完整 DSL 求解和整个 Harness 的质量评测不属于本次范围；当前不可达检查只对支持的表达式做保守静态执行。
