# 对话内结构化待处理操作

主对话区直接展示需要用户决定的事项。按钮和表单绑定服务端保存的任务、版本与范围，不调用协调模型解释按钮含义；明确自然语言表态仍可使用。

当前测试版的费用门禁已关闭（`COST_GATES_ENABLED=False`）。恢复卡片不展示费用额度、未知费用接受或费用补录，费用缺失与超额不阻塞恢复／重跑／队列。新任务标记费用限制禁用；历史金额、未知用量及冻结配置均保留。以下涉及费用门禁的操作仅在以后启用该开关时适用，时间与模型输出限制保持有效。

## 可用操作

| 事项 | 界面与执行行为 |
| --- | --- |
| 阶段产物／章节计划 | 查看固定对象，确认此版本，或在框中填写修改要求；修改生成新稿，不确认旧稿 |
| 阶段／协调 Agent 提问 | 建议选项与自行填写；每次只回答指定问题，剩余问题继续等待；完整问题与答复进入后续执行输入 |
| 原配置续跑 | 保留既有配置、预算与用量；附加时间／费用留空为零，不默认追加 |
| 新配置重跑 | 上游材料有效时创建替代任务及新配置快照；旧任务和运行记录保留 |
| 从 Step1 重建 | 固定当前原作，使用已发布配置，逐阶段重新生成；已被替代的旧流程不可再次恢复 |
| 已知调用缺费用 | 填写实际费用与来源，或主动接受所列旧费用仍未知后创建独立预算的新任务；原始供应商记录不伪造或补零 |
| 排队请求 | 仅恢复选定请求或取消它；不清除其他请求和会话全部暂停依据 |

已交付 Graph 的项目不自动执行全剧重开，以免无授权删除旧章节；页面提示按阶段修订或新建项目。真正远端结果未知时禁用重复执行，并说明仍需核实。技术故障不能通过点击确认伪装为已解决。

## 一致性与来源

- 卡片派生于真实记录，读取不写入配置快照或调用模型。
- 提交在材料、会话与配置锁内重检状态指纹，覆盖固定产物、原作、依赖、预算和当前配置；变化返回 `action_stale`。
- API 校验账号、项目、会话、CSRF 与幂等键。同键同正文返回原结果，不重复写用户消息或任务。
- 用户实际选择保存为真实消息；`action.applied` 记录卡片、动作、状态版本、字段值和回执。替代、费用接受、费用填报分别保留可追溯事件。
- 后台刷新保留输入草稿；失效表单需先查看更新后的内容，费用接受选项须重新主动勾选。请求失败保留输入，相同内容重试复用幂等键。
- 协调澄清使用真实回答消息作为新队列来源，沿原预算和配置继续；不能通过反复答题隐式重置费用上限。
- 原作在点击后、执行前再次变化时暂停，不悄悄切换原文。旧确认、旧运行与未知费用均保留。

## 当前项目阻塞核对

`test` 项目的原作已为 v2，旧 Step1 仍依赖原作 v1，依赖状态为待复核。Step2 旧冻结输出上限为 8000，因输出截断暂停；新发布配置为 100000，但普通继续不会替换旧快照。旧失败调用的终态已确定，费用记录仍未知，当前测试版只保留该费用未知记录，原流程的非费用暂停仍需处理。

对应界面提供“使用已发布配置从 Step1 重新开始”，显示需重建 Step1 的原因和执行时间限额，无费用确认框。直接重跑 Step2 因上游失效而禁用。原队列请求独立保留，可逐项恢复或取消，不随重开自动执行。旧失败调用的未知费用不再阻塞这些操作。

## 验证

自动验证使用真实 PostgreSQL 隔离 schema、模拟模型和浏览器 API fixture，不产生真实模型调用。覆盖当前原作 v2／旧 Step2 输出截断／新配置 100000 的完整恢复链、逐题回答、固定确认、章节修改、费用来源、非法预算、陈旧状态、重复提交、跨项目权限、旧流程不可恢复，以及桌面／窄屏界面。

本次完整后端回归 **258 项通过**（139.70 秒）；前端单元 **27 项通过**；Chrome 操作卡片、错误场景和基础页面三组 fixture 通过。均未使用真实模型。

真实本地服务只读验收通过：当前项目显示 2 张操作卡片、待处理队列 1 项、旧输出 8000／新配置 100000、原作 v2，以及旧分段“v1 · 依赖待复核”。模型调用 **4 → 4**，Task 与 ModelCall 状态及 row_version 均未改变，浏览器业务写请求和页面异常均为零。验收只登录、读取和滚动，未选择或提交恢复操作。证据见[状态截图](../tests/frontend-action-live.png)、[操作选项](../tests/frontend-action-live-options.png)和[只读检查结果](../tests/frontend-action-live-results.json)。
