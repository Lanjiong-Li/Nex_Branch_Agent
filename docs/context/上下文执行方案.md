本文规定上下文组装、Step1 全文或滑动窗口切片、后续阶段材料分批及版本处理的执行规则。Step1 根据固定原作的 token 数决定运行模式；全局事件与主要人物事件由两个专长 Agent 并行扫描，各自推进独立窗口，不创建下游批次清单。配置文件作为开发初值，发布后进入现有 ConfigVersion；主文档中的继承、运行快照、暂停恢复和确认规则继续适用。最终 Graph 字段不因这次拆分而改变。

## 1. 材料绑定与解析

`stage-materials.json` 定义公共材料和各阶段材料。每项指定来源、字段选择器、适用范围、自动／按需加载、是否必需、展开程度、优先级及覆盖要求；内建来源是程序从持久记录生成的投影，不是模型可以随意填写的状态。

加载初值时，将该文件的 profiles、common_materials、内建来源及过滤器注册定义编译为 `context.profiles`；文件中的说明、版本和 schema_catalog 是配置加载元数据，不发送为额外业务正文。`coordinator` profile 对应 conversation_coordinator；aux.summary 由摘要辅助任务使用。Step3 若存在当前有效的 `adaptation_strategy`，会固定并读取该产物版本作为本阶段输入；其初始版本由账号级默认值在创建项目时复制，后续与 Agent 结果沿用同一版本链。

Step9 固定读取 `adaptation_plan`，并由 Harness 按该方案的 `stage_artifact_refs` 解出含叙事功能的游戏事件、结局路线和玩家画像的已确认版本；同时提供本章固定原作正文及 Step9 instructions。当前章节规划没有可核验的原文起止锚点时，正文材料采用固定原作全文。Step9 不自动加载相邻章节设计或其他业务材料，来源版本在保存时由 Harness 关联。

`defaults.json` 顶层的 model、context、adaptation 初始化通用配置；`stage_overrides.step1` 初始化 `scope_kind=stage / scope_key=step1` 的阶段覆盖，其中字段合并到正常的 model、context 配置路径。stage_overrides 是初值加载元数据，不是新的 SDK 参数，也不作为额外层覆盖用户已发布的配置。加载后按主文档的继承规则生成运行快照；页面可编辑阶段覆盖或恢复上层继承，并显示最终值的来源。

解析流程：

1. 从可信运行上下文取得项目、Task、阶段、章节及授权范围，解析配置继承。
2. 将材料的逻辑来源解析为固定产物／决策版本。生产读取适用范围的有效版本；修改任务明确绑定被修改稿，历史查询绑定当时版本。审核按 reviewed_artifact_refs 读取明确指定的候选草稿，保留其真实状态；这是审核输入，不提升为生产有效材料。没有有效版本不得擅自替换为最新草稿。
3. 先检查实际 Schema 版本及消费者映射，再按稳定条目身份筛选，最后展开字段路径。路径中的数组通配符是配置选择器；保存的 EvidenceRef 使用该版本中真实的 JSON Pointer，不含通配符。
4. 每个材料包都附 `record_id / version / item_id / json_pointer`、当前业务状态、实际确认范围、读取范围及依赖。元数据不依赖用户勾选正文项，不能因只选正文而丢失版本或确认依据。
5. 公共材料与阶段材料按“固定来源＋版本＋具体字段／区间”去重；不同版本不得混成一个材料包。当前请求与未完成工具交互保留协议顺序。
6. 检查必需材料和预算，记录 ContextSnapshot 后发送。继续读取保持固定版本；运行期间发现上游变更走影响检查，不在一次组装中悄悄换版。

`auto` 表示调用前自动准备；`on_demand` 表示通过已有只读工具展开。`required=true` 的材料即便采用按需加载，也须在依赖它的具体子任务执行前实际读到并校验，不能只给一个引用就宣称满足需求。后续阶段的必需集合允许分批覆盖；Step1 的本次全文或固定窗口原文必须同时处于切分调用的输入内，不适用下游批次规则。

`full / index / ref` 分别表示完整选定字段、可定位的索引和固定引用。index 只由已保存字段投影，不临时编造摘要；引用或索引不能冒充完整正文。字段存在但值为业务允许的空数组／null，与来源不存在、路径失效、读取失败分别记录。`needs_input` 的空 payload 不能当作完整产物使用。

每个 profile 的依赖范围按[版本映射方案](版本与确认映射.md)登记。自动材料中的全局限制、玩家身份、禁止事项及章节入口／出口契约必须覆盖实际任务；局部筛选不能过滤掉适用的全局约束。字段选择是上下文呈现规则，不自动证明其他字段对语义没有影响。

## 2. Step1 滑动窗口与后续分批参数

### 2.1 Step1 原作输入

| 配置键 | 默认值 | 含义与约束 |
| --- | --- | --- |
| `context.step1_source.trigger_tokens` | 500000 | 原作估算 token 数 **大于**此值时使用滑动窗口；小于或等于时两个 Agent 各自一次输入全文 |
| `context.step1_source.window_tokens` | 300000 | 每个 Agent 窗口内原作正文的 token 上限；各自从已确认覆盖终点重新开窗 |
| `context.input_token_cap` | 阶段继承值 | 整次模型请求的输入上限，另含 instructions、工具和输出合同 |
| `model.max_output_tokens` | 阶段继承值 | 输出预留，包含推理和可见输出 |
| `context.safety_margin_tokens` | 阶段继承值 | 模型窗口的估算安全余量 |

有效输入预算 `B = min(context.input_token_cap, 模型上下文窗口 - model.max_output_tokens - context.safety_margin_tokens)`，分别按两个 Agent 的有效模型与配置核算。发布时要求两个滑动窗口参数为正整数，窗口大小小于两条视图各自的 `B`；运行前仍检查实际完整请求。全文模式若某条视图的实际请求装不进模型窗口，不自动改为滑动窗口，而是暂停并显示预算问题，供调试同学调整配置。窗口模式若本次请求超预算、模型输出被截断或没有可确认的安全覆盖区间，也不推进该视图游标；另一条视图已完成的窗口及 Run 记录保留。用户调整参数并显式继续后，下一窗口可采用新配置，既有窗口的固定来源和索引不改变。

滑动窗口的大小只限制传入模型的原文正文，不改变固定原作。窗口边界可以落在事件内部；Agent 只提交当前窗口中已经完整结束的事件，Harness 从该事件结束处重新开窗，使未完成事件的全部原文出现在下一次输入中。人物视图若确实没有完整的主要人物事件，可以明确声明一个无此类事件的连续空区间，校验后独立推进，不借用全局事件边界。不做自动扩窗。两条视图直接标注固定原作的绝对 UTF-16 索引。

### 2.2 Step2 及后续阶段

下列键均位于 `context.batching`，仅适用于 Step2 及后续阶段的事件集合、章节材料与审核正文；可按 Agent、阶段和辅助任务覆盖，不能覆盖 Step1 全文规则。

| 配置键 | 默认值 | 含义与约束 |
| --- | --- | --- |
| `target_tokens` | 6000 | 每批主要材料目标大小；正整数，不能超过 hard_max_tokens |
| `hard_max_tokens` | 8000 | 每批主要材料硬上限；不包含已单独计量的邻接和衔接材料，不等于单次模型总输入上限 |
| `boundary_order` | `[chapter, scene, paragraph, sentence]` | 按此顺序寻找自然边界；不可用层级跳过；不得擅自改变原作内容顺序 |
| `neighbor_tokens_each_side` | 400 | 前、后各最多 400 tokens，辅助判断边界；不计入本批完成覆盖 |
| `carryover_token_cap` | 800 | 跨批未闭合事件、人物身份和待核对问题的衔接信息上限；详细证据另存固定引用 |
| `max_items` | 40 | 事件／节点集合每批最多 40 条；与 token 上限同时约束，先到者切批 |
| `output_headroom_ratio` | 0.20 | 为输出协议和误差预留 20%；取值 0.1～0.5，不能拿整个输出上限都预算为正文 |

Step2 及后续阶段保持通用默认值 `context.input_token_cap=32000`、`model.max_output_tokens=8000`、`context.safety_margin_tokens=2000`、`tools.read_token_cap=4000`，均按现有配置规则解析；Step1 的较高预算不自动扩展到其他阶段。token 由所选模型适配层估算，保存 tokenizer／估算器版本；暂不支持估算的模型不能默默按“字符数就是 token 数”放行。

先保留 instructions、工具／输出协议、适用约束、当前消息和必要交互，再计算当前调用材料余量 `R`。主要材料实际硬上限为 `min(hard_max_tokens, R - 邻接实际量 - 衔接实际量)`；不足时缩小批次。裁剪顺序仍按主文档 1.6.5，不能用批次配置扩大模型窗口。

6000 tokens 是主要材料的组装目标。Agent 主动用 read_record 展开时仍遵守每次 4000 tokens 的工具返回上限，通过多页完成同一批读取；分页不会变更批次或版本。自动组装器可直接读取同一固定来源，但仍受总输入预算约束。

压缩目标 50% 是对旧工作历史的软目标，不是批次大小；后续阶段必需材料本身超限时按合法工作范围切批，不用摘要冒充正文覆盖。Step1 始终采用 2.1 的全文准入。

`context.history_token_cap` 是历史控制目标，不通过截断完整历史强制满足。完整输入未超硬预算时，固定材料本身超过压缩目标且历史已在控制目标内，不触发重复软压缩；待压缩前缀仅包含当前固定摘要、没有新增原始历史时，也不为软目标再次改写同一摘要。完整输入超过硬预算时仍执行压缩或暂停，不能因上述优化放行。

摘要使用原始归档的可读投影：`reasoning` 项保留固定原档引用、类型、ID 与供应商实际返回的 `summary`，不把 `encrypted_content` 密文当普通文本发送给摘要模型；无公开摘要时保持为空。原始响应、不可变归档和旧代 SDK 工作项中的密文保持原样，工具调用／结果及覆盖记录完整保留。

## 3. 阶段执行顺序

### 3.1 Step1 原作双视图切分

1. 原始附件和解析出的权威文本保存为固定 `source_text` 版本；所有 SourceAnchor 使用这份文本的 UTF-16 半开区间。
2. Harness 估算全文 token 数，按 2.1 选择全文或窗口模式，并行启动全局事件 Agent 与主要人物事件 Agent。全文模式分别在各自一次调用中提供整份原文；窗口模式各自扫描，独立维护 Task、Run、Session、游标和固定原作版本。
3. 全局事件窗口只接受以完整全局事件边界结束的连续覆盖前缀。人物事件窗口以完整人物事件边界提交；若该窗口没有完整主要人物事件，可明确标记连续的无事件区间，Harness 校验其覆盖起止与剩余范围后独立推进，不依赖全局事件结果。
4. Harness 对每条视图分别核对来源版本、绝对 UTF-16 锚点、边界及连续覆盖，逐窗保存游标和响应。全局视图覆盖全篇后保存 `source_global_events`；人物视图覆盖全篇后保存 `source_character_events`。两份产物不合并，且都来自同一固定原作版本、都有效时，下游阶段才可继续；此时各自的 `remaining_source_anchors=[]`。窗口结果不会提前成为有效的最终产物。
5. 输入预算不足、输出截断、没有安全推进区间或覆盖不连续时暂停对应视图，不推进其游标、不跳过原文；另一条视图已完成的进度保留。恢复时使用既有进度和固定原作；若曾取得可复用的完整响应，先核对对应 Run 再重放。

Step1 不创建 `batch_manifest`。来源、每窗 Run 和模型输入输出保留在运行记录中；Step2 起才使用后续材料分批机制。

### 3.2 后续材料的切批与衔接

Step2 以后按阶段任务选取已确认／有效材料：事件和人物优先按已有稳定 ID 分组，正文阅读按章、场景、段落、句子的自然边界处理。主要材料每批唯一归属，邻接仅提供背景；过大的单元可在合法字符边界拆为阅读范围，但不能据此改变 Step1 的事件边界。

使用已有事件和人物身份，不在各批重新建立同名对象。跨批未解决问题和因果约束保存为有来源的衔接信息；歧义交对应阶段 Agent 核实。只有局部任务完成且结果保存后才记录完成范围，读取或摘要本身不算分析完成。

### 3.3 后续阶段复用

| 阶段 | 默认执行单位与合并规则 |
| --- | --- |
| Step2 | 按事件原文顺序，每批最多 40 条且遵守 token 上限；人物视图中没有关联事件的条目另登记补充单元，不能漏读。保存局部分析，再结合全部批次证据，将作品事件视图和主要人物事件视图综合为一份 `source_knowledge_asset`。全局结论必须可追溯，未读远处事件不推断成已核验事实 |
| Step3～Step6 | 按各阶段固定输入加载必要材料；过大的事件集合按稳定 ID 分批。最终产物保留阶段要求的完整内容，各分批草稿不能独立冒充全局结果 |
| Step7～Step8 | Step7 仅依据方案引用的固定游戏事件视图；Step8 仅依据该视图及方案引用的固定结局路线。各自使用独立 Session，来源身份由 Harness 绑定；如需切批，只在这两份固定输入内部划分，不额外带入全局方案或前段会话 |
| Step9～Step10 | Step9 选择已确认游戏事件组成章节；Harness 根据所选事件的已验证原文锚点合并并写入 `chapter_source_anchors`，模型不自报章节原文范围。Step10 使用独立 Session，仅接收已确认的本章完整 `chapter_design`、按固定原作版本提取的对应正文及 instructions；原文可含不相邻片段。Graph 基线和写入元数据留在 Harness 内部，输出仍须是完整 `chapter_graph`，不以首批正文代表全章 |
| Step11 | 固定审核版本清单，按章节内节点顺序分批读正文，登记节点／正文范围覆盖；另做章节连接、共享变量和跨章承接检查。只读过结构索引不能宣称已审核全剧正文 |

Step11 的首次 Graph 来源是程序从已确认章节和冻结基线组装、校验并保存的候选版本。候选无需预先通过 Step11；审核通过后只交付同一候选内容，接口见存储契约 4.3。若审核要求修改，则生成新候选并审核其准确版本。

批次结果过多时按“批次结果 → 分组汇总 → 全局汇总”递归处理，每层保存覆盖集合与原始引用。全局范围要求仍检查所有底层批次完成；汇总无法解决的冲突回读证据。审核报告明确未覆盖项，不能以 token 不足自动通过。

输出预算与输入预算分别检查。输出预计不能容纳时先缩小可合法分批的工作单元；Step9／Step10 的完整章节若仍超输出上限，保存进度并说明需提高输出配置或调整章节边界。提高配置遵守显式迁移，改变业务章节边界遵守用户确认；不能截断 JSON、漏掉正文或私自拆章。首版不引入未经定义的正文片段输出类型。

## 4. 批次清单与恢复

本节仅用于 Step2 及后续阶段，禁止为 Step1 创建原文批次。批次计划保存为 `artifact_kind=batch_manifest` 的内部 ArtifactVersion，`output_schema=null`，由 artifact_kind 与内容 schema_version 路由到下述内部处理器；不是 Agent.output_type，不进入 Nexo Graph。计划修订保存新版本，运行检查点通过 input_refs 固定引用；批次执行以子 Task 和已提交 RuntimeEvent 维护，不把进度写回不可变计划。

内部 `batch_manifest` 内容的固定字段如下，全部必填，除注明可空外不接受 null，不允许额外字段；按 `context.batch_manifest.v1` 处理器验证：

| 字段 | 类型／约束 |
| --- | --- |
| `schema_version` | 固定字符串 `1.0.0` |
| `task_id / config_version_id` | 同项目 Task／ConfigVersion UUID |
| `stage` | 当前具体阶段字符串，使用 stage-materials.json 的 stage 标识；不允许 step1 |
| `generation` | 从 1 递增的计划代次 |
| `input_refs` | 非空 EvidenceRef 数组，所有内容版本固定 |
| `units` | 非空数组；每项 `{unit_id:string,source_ref:EvidenceRef,start_utf16:integer|null,end_utf16:integer|null,content_sha256:string}`；正文区间必须成对且 `0 <= start < end <= 文本长度`，结构条目两偏移均 null，以 source_ref.item_id／json_pointer 定位；hash 为实际选取内容的 SHA-256 |
| `batches` | 非空数组；每项 `{batch_id:string,sequence:positive_integer,owned_unit_ids:string[],context_unit_ids:string[],boundary_split:boolean}`；主要集合非空，每个 unit 恰由一批拥有；邻接可引用其他批拥有的 unit，其展开受邻接预算约束 |
| `estimator_version` | 实际 token 估算器的非空版本字符串 |

空原作不创建空计划，返回缺少可处理正文。结构集合没有条目时由阶段规则判断空结果是否合法，不创建一个假批次。程序校验 unit 引用、范围并集、唯一归属、输入 hash 和固定来源，不由模型自行证明全量覆盖。

执行事件 `context.batch_completed` 的 payload 固定为 `{manifest_ref,batch_id,task_id,result_refs,processed_unit_ids,unresolved_refs}`；引用使用 EvidenceRef，task_id 为实际子任务 UUID，result_refs 非空，processed_unit_ids 只能来自 owned_unit_ids。未完成或有阻塞问题的单元不计入 processed。事件、保存结果与 Task 状态按现有事务规则提交；由这些记录重建进度，不另设前端权威状态。

恢复先读固定计划和完成账本，复用已经提交的结果；失败／未处理范围才继续，未知调用先走运行恢复核对。一个批次允许完成部分主要单元，剩余单元在同一任务范围续跑并去重记录，不能把一次部分成功当整批完成。更改原作或切批参数产生新计划，仅在固定内容、完整输入与任务语义均证明一致时复用旧结果并记录依据，其余重做。不能只因 batch_id 或文字相同就沿用旧状态。

## 5. HTML 配置及可视化

沿用同一对话页中的配置区和运行与数据区，不另建管理站点。下面的“编辑”都是 ConfigVersion 草稿编辑；保存不立即影响运行，发布前统一校验，恢复默认使用旧快照。

| 页面位置 | 功能 |
| --- | --- |
| 上下文 → 阶段材料 | 展示来源产物、字段树、筛选范围、自动／按需、必需程度、展开程度和优先级；可按阶段覆盖、恢复继承；展开时附字段中文说明与实际路径 |
| 上下文 → Step1 滑动窗口 | 在全局默认调整触发阈值与窗口大小；显示原作 token、当前输入模式、固定版本、各视图游标及有效预算 B |
| 上下文 → 后续阶段分批 | 编辑本方案 2.2 参数；边界顺序只能选择已实现策略，Step1 不使用此页配置 |
| 输出兼容性 → 依赖与版本映射 | 编辑已注册字段／身份映射和无语义转换的参数，预览影响的消费者与确认范围；具体要求见版本映射方案 |
| 组装预览 | 选择真实固定版本与任务范围，展示自动材料、待展开材料、缺失字段、必需覆盖、token 估算及超限原因；只读预览不调用模型、不生成产物、不登记确认 |
| 分批预览 | 对后续阶段的固定事件、章节等材料显示批次边界、主要范围、邻接、预计 token 和批次数量；调整后显示新旧边界差异；Step1 分别预览两条视图的全文或窗口准入 |
| 运行与数据 → 覆盖 | 查看计划版本、逐批状态、实际覆盖／剩余范围、对应结果、未解决跨批事项、恢复复用依据；原文高亮可跳回准确固定版本 |
| 运行与数据 → 影响与确认 | 展示上游改动、受影响对象、仍有效范围、需复核范围及确认来源；查看和比较不会自动确认 |

发布前必须验证：字段路径在对应 Schema 版本存在；身份／来源元数据完整；阶段必需语义仍有可执行读取途径；范围过滤器和转换已经注册；数值范围和总 token 预算可成立；Schema 改动连同消费者和确认路径迁移通过样例。将必需项标为可选或移除，只有已注册的替代输入／流程明确满足同一阶段契约才能发布。

自动继承确认仅适用于已验证未改变的范围，不能通过 UI 设“默认确认”绕过。配置中的优先级只影响可选材料的取舍，不能将低优先级必需材料静默丢弃。

## 6. 开发验收

| 场景 | 预期 |
| --- | --- |
| Step10 读取章设计 | 读取固定已确认范围、完整正文及互动逻辑；来源与输入清单可核对 |
| Step1 某条视图的原文或完整输入超限 | 不启动该视图的模型切分，显示限制；不摘要、截取前段、分页累积或创建批次降级，另一视图的进度可保留 |
| 第 1～15 场属于同一事件 | 全文模式提供整份原作；窗口模式不得把未结束事件标为完成，下窗从该视图尚未提交的位置重读，窗口内始终无法安全推进时暂停 |
| Step1 修复或恢复 | 两条视图各自复用已验证窗口；需重新切分时仍有完整原文，输出不完整不标成功，分别重新核验预算 |
| Step1 窗口达到配置的 token 上限 | 仍需计入 instructions、工具与输出合同；超过实际硬预算时暂停该窗口，不推进游标 |
| 在配置页更换模型或恢复预算继承 | 重新计算 B 并校验原文及输出限制；非法组合不能发布；有效新配置不悄悄改写已有运行快照 |
| 后续章节材料超长或含 emoji | 合法分批阅读，UTF-16 范围完整无遗漏，邻接不重复计入覆盖，已有事件身份保持 |
| 后续批次中途失败后恢复 | 已提交批次复用、未完成单元继续、未知外部调用先核对，原任务预算不清零 |
| 查看新批次配置预览 | 旧运行仍用旧计划和快照，预览不产生覆盖或确认记录 |
| 字段改名、删除或源 Schema 变化 | 发布前显示具体失效绑定，完成已注册映射后才允许新消费者使用 |
| 只改一章或条目在数组中移动 | 按版本映射复核实际影响；历史引用保持固定，无证明的范围不继承确认 |
| 全章输出或全剧审核超预算 | 缩小合法工作单元／分批汇总或返回明确阻塞；不以截断产物、索引或局部审核冒充完整完成 |

以上是执行正确性要求，不增加 Harness 创作效果评测模块。

离线运行 `python docs/context/validate.py` 可核对默认参数、注册来源和阶段字段路径；它不调用模型，也不证明业务语义、生产调度或页面已实现。
