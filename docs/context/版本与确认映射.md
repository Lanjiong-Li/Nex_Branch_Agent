# 版本、依赖与确认范围映射

本契约定义上游变更后的范围定位、影响复核和确认继承。记录复用 [Harness 数据契约](../harness-data/README.md)，任务暂停与恢复遵守[运行状态机](../runtime/运行状态机.md)。规则由服务端执行，不增加业务 Agent、人工审批节点或首版 Graph 质量算法。

## 1. 固定身份与范围

| 对象 | 定位规则 |
| --- | --- |
| 产物／决定 | 使用逻辑 ID 与具体版本；`EvidenceRef.version` 必填十进制版本字符串，禁止以“最新”替换历史引用 |
| 条目 | 使用产物内唯一、跨版本稳定的 `item_id`；保留既有事件、角色、章节、节点等 ID，新条目由程序分配，禁止按数组序号重建身份 |
| 字段 | `Selection.json_pointer` 是指定版本根对象内的绝对路径；条目字段同时携带 `item_id`，必须验证路径确实属于该条目 |
| 顺序／成员关系 | 数组顺序和集合成员分别作为结构依赖保存；事件先后、章节顺序、分支优先级属于业务语义，不视作纯显示变化 |
| 无内置 ID 的材料 | 服务端保存版本化身份索引，关联固定原作范围、父条目和位置；不向最终 Nexo Graph 塞入 Harness 字段 |

条目身份仅表示“同一个对象”，不表示内容未改变。原作段落移动、同文重复、人物同名均不能仅凭文本相似度认定身份；候选匹配可由模型提出，程序仅接受明确编辑沿袭或唯一且完整的来源映射。无法唯一定位时标记 `unresolved`，不自动继承确认。

原文位置使用固定 `source_ref` 及半开字符范围 `[start,end)`；范围只在该原作版本内有效。新版本中的同一段落需要单独登记稳定身份和沿袭，不能将旧偏移直接套用新版，也不能因新旧片段文本相同就把跨版关联记为已验证。

`item_id=null,json_pointer=""` 表示完整对象。完整对象确认可按已登记的字段／条目边界保留其中未变部分，但必须同时保留该部分的语义保护范围；无法拆分的整体选择保持整体确认单位。不能把对一条路线的整体认可解释成对任意重组片段的独立认可。

## 2. 依赖登记与语义保护范围

每次生成记录实际读取的固定材料及字段。`Dependency.producer_selections` 保存材料范围，`consumer_selections` 保存受其约束的输出范围；无法明确对应时，消费者默认整份阶段产物或当前完整章节，禁止猜测更窄的依赖。

默认保护范围包含：所选字段、条目身份与所属章节、具有业务意义的顺序／成员关系、关联人物／事件／变量身份、适用决策、角色所知信息与前置因果约束。全局保留要求、玩家身份、禁止结局等全局约束关联全部相关消费者。读取完整数组用于“全量分析”时，数组成员关系也必须登记，避免新增事件被漏判。Step1 的双视图切分对完整原作版本登记依赖；局部事件的来源范围用于定位证据，不能将全本切分的依赖缩成该片段。

阶段字段配置可以扩大保护范围、指定已登记字段间的依赖关系；不能删除执行该阶段必需的约束。字段绑定或 Schema 缺少明确规则时，扩大到父条目或完整产物，仍不明确则暂停依赖该材料的生产并报告缺项。

## 3. 变更处理

| 变更 | 默认处理 |
| --- | --- |
| 仅版本号、非业务审计元数据变化 | 业务内容、身份、语义保护范围和依赖均验证未变，可保留确认与有效性；忽略字段必须在服务端白名单内 |
| 同一条目修改字段 | 修改字段及其保护范围进入复核；其余字段仅在可独立确认、完整证明未变时继承 |
| 移动条目／数组重排 | 身份可保留，路径重算；业务顺序、归属或因果发生变化时，不因正文相同继承相关确认 |
| 新增条目 | 分配新 ID，新内容不继承确认；复核读取集合成员关系、全局约束或新增条目引用的消费者 |
| 删除条目 | 保留旧版本和旧确认；新版本没有对应确认范围，引用该条目的消费者进入复核；失去必需来源或悬空依赖时为 `invalid` |
| 拆分／合并条目 | 新对象分配新 ID，保存多对多沿袭；默认需要重新确认，不能按文本覆盖率自动平摊或合并旧确认 |
| 原作正文改版 | 保存新版本并重新检查全文准入；Step1 在每次模型调用中同时加载新版全文，重新检查全本事件边界与双视图，不只重做改动片段或批次。映射原文与双视图后，后续阶段中内容、身份、语义保护范围和依赖已完整证明未变的结果可保留，其余按实际影响复核或重做 |
| Schema 改名／结构移动 | 仅使用指定版本的已注册转换，另存新产物版本；逐项证明字段意义、类型、约束、身份和依赖未变后才能继承 |
| Schema 新增／删除字段、类型或枚举变化 | 新增和语义改变范围不继承；删除字段不映射为空值表示“已确认”；转换失真、消费者不兼容或规则未知时阻止生效 |

任意正文改写，包括看似普通措辞变化，都不能只凭模型判定“意思一样”自动迁移该字段的确认。其他未改且独立的内容可以保留。纯 JSON 格式变化可以规范化比较；默认只忽略对象键顺序与 JSON 序列化空白，不忽略正文空白、标点、数组顺序或业务字段。

## 4. 影响判定算法与职责

1. 固定旧／新产物版本、Schema 和配置，读取完整候选范围及原始确认依据。新草稿仅计算影响预览；用户明确要求改变现行要求，或新版本依阶段规则获准作为当前依据时，才执行对应范围的生产限制。
2. 程序按稳定身份建立字段差异与范围映射，标记新增、删除、移动、修改、拆分、合并和未知。路径相同、内容哈希相同或模型相似度均不能单独证明业务未变。
3. 从反向依赖索引定位候选：字段相交、父子范围包含、引用关系、集合成员／顺序或全局约束发生变化即命中；沿被影响消费者范围向下传播，去重并保留传播链。
4. 在生效切换事务中，将尚未判明的候选 `Dependency` 标为 `review_required`，受影响任务按运行契约暂停后续生产；无关范围继续。明显失去必需材料／确认的依赖标为 `invalid`。
5. 对应阶段的既有 Agent 读取差异、相关原文及消费者，提出“可复用／需修改／需用户取舍”的简短语义复核和依据。Step1 重新切分或修正必须同时读取固定版本的完整原文，不能只凭差异片段处理。协调 Agent 负责向用户解释与安排修复；不新建常驻影响分析 Agent。
6. 程序核验复核依据、范围完整性与依赖状态。完整证明未变的范围可恢复 `valid`；已确定不满足新要求的范围为 `invalid`；语义影响仍无法排除的范围保持 `review_required`。模型单独给出“无影响”不能解除检查或签发确认。
7. 确认继承通过第 5 节规则后提交；需要修复的范围在已授权任务内保存新草稿，仍遵守原阶段确认条件。新材料、变更范围或新的创作取舍交用户明确表态，不重新确认无关内容。

下游依赖的旧 `producer_ref` 始终保留真实生成依据。证明新旧所用范围等价时，可用评估记录说明旧产物仍兼容当前要求，无须伪造“曾读取新版”的历史。若重新绑定输入、迁移内容或重新生成，必须保存新消费者版本与新的 Dependency，不原地替换旧引用。

语义复核发现“内容不同但可以继续使用”时，保留复核建议并请求用户确认该变化或调整要求；该意见不能作为 `unchanged_scope` 的证明。用户明确确认后以新依据完成必要复核，不把用户确认冒充程序质量检查。

## 5. 确认继承的必要条件

仅当以下条件全部满足，服务端才生成 `Confirmation.basis=unchanged_scope`：

- 原确认真实、未被撤回，来源用户消息可追溯；映射范围是原确认实际覆盖范围的子集。
- 新旧范围均可准确解析到存在的固定版本；身份映射唯一，一对一，没有把新增、拆分或合并内容包含进去。
- 内容逐字段相同，或通过已登记且证明语义不变的转换；比较覆盖业务内容，而非仅比较哈希或字段路径。
- 所属语义保护范围未变；适用决策、原作依据及关联依赖有效，所有相关变更已完成有依据的复核。
- 目标范围不含待确认新增内容，当前状态没有新的撤回、变更请求或冲突；提交时重新核对条件版本。

继承产生新确认记录，`source_message_ids` 保留原真实消息，`carried_from_confirmation_ids` 指向旧确认，`scope_mapping_ref` 指向程序核验后的映射事件；不制造新用户发言。只有全部必须确认范围覆盖时，目标才可为 `confirmed`；否则为 `partial` 或 `unconfirmed`。确认、依赖有效、质量通过三个状态继续独立。

整份方案增加新条目时，旧内容即使全部可继承，也不能生成新版全对象确认。后续用户只需确认实际新增／变化范围；程序再核验合并后的覆盖是否完整。用户确认一次明确列出的多个范围可以一次保存，无须逐字段点击。

## 6. 持久化与提交接口

范围索引、比较和评估使用只追加的 `RuntimeEvent`；内容草稿及既有阶段复核产物使用 ArtifactVersion，不新增第 23 种核心记录，也不修改 output_type。事件外壳通过内部 Schema 后，payload 另按下表做严格字段和引用校验，模型不能直接签发事件。

| `event_name` | 必需 payload 字段与约束 |
| --- | --- |
| `artifact.identity_indexed` | `handler_version="context_mapping.v1"`、`subject:Ref`、`entries:[{item_id,json_pointer:string\|null,parent_item_id:string\|null,source_span:{source_ref:Ref,start:integer,end:integer}\|null,source_refs:Ref[]}]`；同版 item_id 唯一，结构条目路径唯一；原作正文以非空 source_span 定位，结构材料以非空 json_pointer 定位；所有位置与来源实际存在 |
| `artifact.scope_compared` | `handler_version`、`from_subject:Ref`、`to_subject:Ref`、`config_version_id:Id`、`entries:[{from_selection:Selection\|null,to_selection:Selection\|null,change_kind,transform_id:string\|null,evidence_refs:Ref[]}]`；两端不能同时为 null，kind 为 `unchanged/modified/moved/added/deleted/split/merged/unresolved` |
| `dependency.assessed` | `handler_version`、`comparison_refs:Ref[]`、`dependency_ids:Id[]`、`assessments:[{dependency_id,state,consumer_selections:Selection[],candidate_producer_ref:Ref,reason,evidence_refs:Ref[]}]`；state 沿用 `valid/review_required/invalid`，逐条覆盖本次候选；业务产物引用固定版本，结论对应具体证据 |
| `confirmation.scope_mapped` | `from_subject:Ref`、`to_subject:Ref`、`entries:[{from_selection:Selection,to_selection:Selection,unchanged:true,evidence_refs:Ref[]}]`、`dependency_assessment_refs:Ref[]`；只包含第 5 节通过的范围，每条新范围唯一，旧确认通过后续 Confirmation 明确关联 |

前三种事件的 `handler_version` 均为 `context_mapping.v1`。`Ref` 沿用 EvidenceRef，`Id` 为 UUID；上述字段全部必填，nullable 字段显式 null，不接受额外字段。比较／评估／确认映射的 entries、comparison_refs、dependency_ids、assessments 和每项 evidence_refs 均非空；身份索引允许空 entries 表示空材料。大型比较可分为多个同版本事件，最终评估逐一引用；不能因分页只读到首批就宣称完整覆盖。程序验证事件持有的内容和引用，不接受客户端传入的“已证明”布尔值作为证据。

服务端按 event_name 和上述 handler_version 注册严格载荷处理器，字段契约即上表；已有 confirmation.scope_mapped 沿用数据契约的事件格式。业务产物引用须解析为具体 ArtifactVersion／Decision 版本；comparison_ref 指向 artifact.scope_compared，assessment_ref 指向 dependency.assessed，scope_mapping_ref 指向 confirmation.scope_mapped。普通事件引用 version=null，身份／路径／同项目校验不得因外壳 Ref 合法而省略。

新增服务端内部命令 `commit_dependency_assessment`，不暴露为 Agent tool，使用既有 AuthContext、项目隔离、幂等和运行租约约束：

- 输入：`comparison_refs:Ref[]`（非空）、`assessments`（上表同型非空数组）、`expected_dependency_row_versions:[{record_id:Id,row_version:integer}]`、`expected_artifact_state_row_versions:[{record_id:Id,row_version:integer}]`。服务端重新验证候选、证据和目标范围，拒绝未覆盖候选或竞争变化。
- 输出：`{event:Record<RuntimeEvent>,dependencies:Record<Dependency>[],artifact_states:Record<ArtifactState>[]}`；同事务保存评估事件、依赖状态及产物状态投影，任务控制事件按运行契约同事务登记。
- `ArtifactState.dependency_status` 默认汇总为：有任一必需 `invalid` 则 invalid，否则有待复核则 review_required，否则 valid。范围级复核以 Dependency 和 selections 为准，无关条目仍可读取和继续任务。

命令只接受注册的 `context_mapping.v1` 程序处理器调用，禁止浏览器／Agent 直接提交生效状态。条件版本均为正整数，覆盖全部实际更新的记录；锁定并重检相关产物、确认撤回状态、依赖和配置后执行 CAS。所有评估、材料和证据必须同项目，candidate_producer_ref 只能是本次差异中的目标版本；`valid` 必须具有第 4 节要求的程序证据，涉及确认继承另须满足第 5 节。Agent 复核建议本身不构成程序语义证明。任一项目、租约、handler、载荷结构、引用类型、证据或条件版本不符，整笔拒绝，不部分提交状态。

确认继承调用现有 `record_confirmation`，使用相同事务中的 `confirmation.scope_mapped` 事件和状态条件版本；服务端可信映射处理器负责该事件，不提供任意事件写入 API。映射、确认、有效范围投影一起提交，失败全部回滚。撤回、版本竞争、字段不存在或证据失效时返回既有 `version_conflict`、`dependency_changed`、`ambiguous_target` 或 `schema_validation_failed`，不尝试绑定最新版重放。

## 7. HTML 配置与展示

在同页“上下文配置 → 版本与依赖”中编辑，纳入不可变 ConfigVersion 和运行快照：

| 配置 | 默认 | 可调整范围 |
| --- | --- | --- |
| `context.version_mapping.field_mappings` | `[]` | 指定来源／目标 Schema 版本的字段路径及稳定 ID 路径；普通同版字段由注册 Schema 解析，不靠手填列表 |
| `context.version_mapping.dependency_scope` | `selected_with_guards` | 可扩大为 `item` 或 `artifact`；所有模式均保留必需语义保护范围，不能选择无依赖模式 |
| `context.version_mapping.extra_guard_paths` | `[]` | 增加字段关联、集合成员及顺序保护，路径必须解析且与绑定 Schema 相容 |
| `context.version_mapping.transforms` | `[]` | 选择服务端已注册的转换 ID／版本和通过参数 Schema 的配置；无任意 Python／JS 或自由表达式执行 |

配置列表使用下列封闭条目，字段全部必填，来源／目标版本为 Schema 版本字符串，字段路径使用 stage-materials.json 的选择器语法；实例中的映射事件仍使用准确 JSON Pointer：

- field_mappings：`{schema_id,from_version,to_version,from_pointer,to_pointer,from_identity_pointer,to_identity_pointer,transform_id}`；字段值均为字符串，两个 identity_pointer 可为 null（仅适用于无条目身份的根标量字段），transform_id 包含已注册版本，如 rename_field@1。同一版本对的目标路径不得冲突，数组内映射必须提供可验证的稳定身份。
- extra_guard_paths：`{schema_id,schema_version,selected_path,guard_paths:string[]}`，guard_paths 非空；仅扩大同 Schema 内的相关语义范围，跨产物依赖通过阶段材料和实际 Dependency 登记。
- transforms：`{transform_id,parameters:object}`；首版三种转换的 parameters 固定为空对象，位置由 field_mappings 指定。新增参数须先有服务端注册的参数 Schema，不能把页面输入当可执行代码。

发布配置前展示旧／新路径预览、无法映射范围及依赖扩大范围。未注册转换、丢失必需字段、身份冲突或无效路径拒绝发布；当前运行不随发布改变固定依据。自动确认规则不是可关闭的配置项，页面不能通过“强制继承”绕过第 5 节。

首版仅登记 `identity@1`、`rename_field@1`、`move_field@1`；后两者只允许字段意义、类型、约束和归属保持一致的结构变换，由服务端适配注册表声明支持的 Schema 版本对。文字润色、字符串与数字互转、枚举替换、补业务默认值均不属于无语义转换，不能借配置获得确认继承资格。

数据区展示固定版本差异、条目沿袭、受影响阶段／章节、依赖传播链、可保留及需重新确认范围、原始确认消息与判定依据。只读展开和预览不触发确认；用户仍在对话中提出修改和确认。
