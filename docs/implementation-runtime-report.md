# 流程引擎与 Graph 运行实现记录

更新：2026-09-21。范围：`engine.py`、`workflow.py`、`graph.py` 及其 PostgreSQL 集成测试。生产运行只调用注入的真实 ModelService；测试使用显式合成模型，不构成真实模型效果验收。

## 已实现

- PostgreSQL 持久 Queue、消息幂等键、同 Conversation 串行、Work Session 租约、心跳与 fencing。已归档 Project 不参与调度；缺少可信运行投影的遗留 Task 暂停为 `checkpoint_invalid`，不猜测恢复内容。
- Task 与 Run 分离；关闭的 Run 不重新开启。Steer 固定目标 Run，Queue 按序保存，Interrupt 先落停止意图。停止宽限到期撤销 Run／Session 持有权，未决请求保留 unknown，迟到结果不能覆盖业务产物。用户等待不计执行时长。
- 预算由预算根 Task 汇总 ModelCall 与辅助工作；未知费用不视为零。cost／active_seconds 的显式禁用、手动追加、子树恢复、独立 Queue hold、已知输出复用均有实现。父调用耗时扣除已单独记账的辅助摘要时间，防止重复计量。
- 崩溃恢复以检查点、固定配置和操作状态为依据；未知外部请求不自动重发。已保存响应经正常 Steer／预算／依赖检查路径提交，不直接跳过控制门。协调回复暂停后可复用已保存响应。
- Step1–11，Step2–10 的真实用户确认、章节建议与范围确认、每章 Step9→Step10、独立整剧审核。确认只引用真实当前用户消息及该消息提交时已经展示的固定版本。关键保留项、玩家身份和改编约束由真实产物确认派生版本化 Decision，普通措辞不单列决策。
- Step1 始终完整读原文。来源锚点可使用合法非空 UTF-16 区间且 quote=null，避免在输出中重抄全本；提供 quote 时逐字核对或唯一定位，拒绝歧义、越界及拆开代理对。
- Step2–8 超出输入预算后，保存固定 manifest，真实执行 aux.subtask 子 Task／Run，提交真实局部产物和逐单元覆盖账本。所有批次完成后，Step2 父任务输出全局事件分析与主要人物事件分析两部分，Harness 分别保存；Step3–8 输出各自完整 Schema。辅助配置从父快照冻结的 auxiliary_configs 派生；不读取运行期间新发布的配置。邻接资料不计拥有范围，carryover 受预算控制。同一批未完成的剩余单元使用新的子任务键，不能复用先前局部结果冒充处理。
- 全部业务 EvidenceRef 检查真实项目／固定版本、具体 JSON Pointer 与匹配的条目身份。所有有效产物切换递归标记受影响依赖；纯程序 stage_artifact_refs 索引写回不会将整个流程循环失效。解释修改请求的普通协调任务可读取旧版本，不因自己发起变更而误暂停并遗留队列 hold；实际生产依赖仍会暂停。
- Graph 验证与组装使用固定 ConfigVersion 的 Schema，支持已发布的兼容字段扩展。Step10 基于真实冻结基线验证完整章节、删除范围、身份、类型和布局；新身份经程序检查并登记。最终候选继承已交付基线和原工程额外字段侧存。
- 历史基线完整保留 source_refs，但不作为随被替代旧稿失效的活动 Dependency，避免旧章节→基线→新版章节的自失效。当前创作材料仍建立真实依赖。
- Step11 之前先组装并保存固定候选及两项程序检查；审核必须引用同一候选、标准与实际检查记录，覆盖全部已确认章节。通过后只交付该版本。下载／状态从 `project.delivered` 固定引用读取，不把最新草稿误当交付。

## 验证

测试均使用独立 PostgreSQL schema 并在结束后清理，避免合成任务进入真实 worker。

- 一轮 Runtime＋Graph 共 21 项通过（248.84 秒）；随后 nullable SourceAnchor 与 Graph 专项 7 项通过。
- 完整双章模拟最终定向通过（1 项，41.56 秒）：每个阶段实际执行 context.prepare/build，以真实 HistoryRecord 确认，冻结 candidate→review→delivery；随后修改已交付第一章、再次确认与审核交付，验证未修改第二章、节点 ID 与制作基线保留。
- 修订请求协调任务不自暂停、真实生产依赖仍暂停的专项通过（1 项，6.07 秒）；已归档项目不调度专项通过（1 项，6.92 秒）。完整统一测试结果由项目验收记录汇总。
- 输出 EvidenceRef 路径缺失单独记为 `evidence_pointer_missing` 并进入有限修复；必需输入字段缺失仍暂停，未纳入泛化重试。引用身份与上述分类专项 3 项通过（3.88 秒）。
- 协调输入保留 Task 结构化目录与真实引用，不重复注入历史 Task 的请求描述、用量、预算和存储元数据；待用户项、提交时已展示版本及确认范围保持原样。跨 Session 的 work_summary 不由 Engine 自动全量载入。使用真实 smoke 固定 Run 只读测量，runtime.status 从 9,638 降至 2,006 tokens（减少 79.2%，原 14 个任务引用全部保留，另包含之后产生的 1 个任务）。目录／确认范围专项和双次交付回归共 2 项通过（27.13 秒）。
- 明确继续父批次任务时，直接 batch_owned 子任务若因证据校验暂停且已有持久 ready 输出，可重新校验该输出，无需再次请求模型。unknown 类暂停未放开；提交前仍检查预算、Steer、固定依赖及 fencing。正常批次、零新增模型调用的批次恢复、子树继续共 3 项通过（14.05 秒）。
- 批次 `needs_input` 与普通阶段共用真实提问／等待流程，父任务等待同一批次的补充；未完成范围不计入覆盖。用户通过真实消息与协调意图继续后，仅提问的子任务读取补充并继续原 Session／配置／manifest，已完成批次不重跑。旧 `paused(batch_needs_input)` 记录可明确继续父任务，以零新增模型调用展示已保存问题，再正常答复。四种批次路径、普通问答和双次交付共 6 项通过（47.20 秒）。
- 批次 recovery Run 与待复验响应及 `source_run_id` 在同一事务提交，明确标记没有派发模型；旧版事务间隙留下的恢复 Run 可验证 `resume_saved_result` 所属 Task、固定配置及真实源响应后继续。崩溃注入覆盖新原子路径与旧版缺复制响应路径，均零新增模型调用。六种批次路径专项通过（29.45 秒），未将无供应商调用的 recovery 误判为外部操作未知。
- 协调结果把 `continue` 指向顶层任务时，沿真实同会话父子链定位已展示的待答项：优先匹配原用户消息中的待办 ID，否则要求范围内唯一待答项。多个候选、尚未展示的问题及 confirmation 不会被猜测为已回答；转发事件记录请求目标、实际子任务、待办与原消息 ID。顶层到批次问答、歧义／确认保护及原问答兼容共 8 项通过（18.89 秒）；真实 smoke 只读路由验证准确关联原答复与原待办，未写入事实。
- 新停止操作记录共享 `stop_command_id`。父任务明确继续时，仅清除同一停止命令中已失败的 parent_owned 摘要子任务所留 `user_stop` hold，且必须有真实停止事件链并无未明模型调用；失败摘要保持原记录，不重启。其他原因、其他命令和缺少命令证明的旧 hold 保留，旧记录可由明确 `resume_queue` 操作处理。专项及原子树继续共 7 项通过（4.44 秒）。
- 模型输出引用解析时，仅将 Store 的四类明确固定引用错误转为 `evidence_reference_invalid`（保留原引用及原因），其他数据库 `InvalidRecord` 原样抛出。普通阶段和批次均沿固定配置的有限修复额度；批次保留坏响应审计，但下一轮不会重放已拒绝响应，修复通过前不计覆盖，耗尽后父子任务暂停。新增引用分类／阶段及批次有限修复共 9 项通过（11.43 秒）；相关既有输入缺失、批次问答与恢复、Steer 和协调缓存回归共 14 项通过（46.60 秒，含 2 项新增批次用例）。未请求真实 API，未修改真实 smoke 状态。
- 所有阶段与批次在安排修复前标记拒绝响应，包括已耗尽修复额度的最后一次输出。显式继续、旧 resume 缓存、父子批次继续及崩溃恢复统一排除拒绝来源，并沿 `source_run_id` 识别恢复副本；兼容旧 Run 中已有的校验失败／修复耗尽记录。原响应及审计记录保留，缓存重放不消耗修复轮数；未知调用仍阻断。`坏→停止→继续→坏→好`、触限后继续、批次恢复副本等相关专项 21 项通过（65.37 秒）。本次只使用隔离 PostgreSQL 与 FakeModel，未请求真实 API。
- 新增多批次辅助任务、非法 EvidenceRef、原作更新递归失效、恢复消费 Steer、协调响应缓存恢复、子树停止恢复、共享预算追加及已归档项目不调度回归。
- FakeModel 仅验证调度、数据契约、权限来源及状态一致性。真实 API 密钥加载问题已由 ModelService 修复，最小 Agent／Runner 调用已通过；真实模型完整流程与创作质量的验收另行记录，不以这些合成测试替代。

## 仍保留的明确限制

- Step9／Step10 超大完整章节、Step11 超大整剧无法在当前预算内安全处理时暂停；尚未实现这些阶段的分批正文／Graph 合并与逐批整剧审核，不能用摘要假装完成。
- Step2–8 全部局部结果汇总仍超限时保留进度并暂停；递归多层汇总尚未接入。
- 程序质量检查仅启用 Schema 与章内边端点两项。其他 DSL、叙事、跨章承接、共享对象语义由生成约束与审核 Agent 判断，没有伪报为已运行算法。
- 节点／连线删除及共享对象变更必须有明确范围。当前没有把任意自然语言请求自动转成删除许可；范围不足会阻断并保留草稿。
- 原工程额外字段有侧存与恢复能力；完整 Nexo 编辑器领域对象的导入／回写适配不在当前接口验收范围。
