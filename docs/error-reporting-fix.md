# 模型错误分类与展示

当前实现将“已收到失败或未完成响应”与“无法确定请求结果”分开处理。适用于当前安装的 Agents SDK 0.22.2，相关供应商边界由真实 SDK 配合本地 HTTP fixture 验证。

| 原因 | 运行错误码与处理 |
| --- | --- |
| 输出达到上限 | `output_limit_exceeded`；提示本次冻结的 `max_output_tokens`（含推理），暂停，不自动重发、不接受截断产物 |
| 内容策略或其他未完成原因 | `response_incomplete`；显示受控 `incomplete_reason`，内容策略明确说明 |
| 供应商明确失败 | `response_failed`；保存安全的供应商错误码 |
| 明确拒答 | `model_refusal`；不把拒答当作有效产物 |
| 结构或工具协议异常 | `ModelBehaviorError`；保留已收到响应的真实用量，按既定有限修复规则处理 |
| 凭据、权限、余额、频率、模型、上下文或 Schema 错误 | 分别归类并保留 HTTP 状态；未识别原因保持未知，不臆测、不直接展示原供应商错误正文 |
| 无终态的断线／超时 | 调用保持 `unknown`；`operation_uncertain` 防止未经核对重发 |
| 已收到终态，但缺少可核实费用 | 新请求由 `usage_uncertain` 阻断，失败调用不能当作零费用 |

`model_service.py` 在 SDK 丢弃未完成响应之前保存终态、输出、供应商响应与用量。失败终态不产生可恢复的有效产物，也不写入成功的会话输出。安全诊断随 `ModelRunError.details` 保存到 `Run.error`；页面显示中文原因、错误码及对应 Task／Run，可追到当前阻断子任务。原始供应商消息、密钥与完整响应不直接拼进错误提示。

配置仍按任务冻结。发布新的输出上限不会改写既有任务的快照；继续原任务沿用旧配置，需要新配置时重新创建相应阶段任务。

## 旧记录更正

维护函数 `reconcile_legacy_output_limit()` 只接受精确 SDK 终态诊断、同项目同任务的最新失败 Run 及唯一关联的 unknown ModelCall。一次事务保存更正前快照与更正事件，更新错误分类，保留原始响应／用量空值、预算、修复次数和调用起止时间，任务仍暂停，不启动模型。

2026-09-21 的本地 `test` 项目已执行此更正：原错误为 `response.incomplete`／`max_output_tokens`，冻结上限8000；更正事件为 `b5dba0cd-45e1-40f4-9f3a-5a7995514558`。调用计数保持3，原作与已完成 Step1 产物保留。旧调用未归档的用量仍为空，费用门禁继续生效；更正不表示该次生成成功。
